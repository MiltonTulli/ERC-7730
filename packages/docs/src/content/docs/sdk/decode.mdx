## What to show

- Prefer `interpolatedIntent` when present (spec option 1).
- Otherwise show `intent` + `fields`.
- Surface `warnings` (e.g. `infinite_approval`, `no_trusted_attestation`, `interpolation_failed`).
- Nested `format: "calldata"` fields expose `field.embedded`. Multicall3 / Safe CALL / UserOp expose `children: DecodedOperation[]` with per-child `source` and `trust`.
- `locale` only formats numbers and dates. Descriptor intent strings are never translated.

## Trust policy

When `trust` is omitted, decode uses `officialOnlyPolicy()`. `DecodedOperation` remains the source of truth. The old `format` / `formatTypedData` aliases are removed; see [Migrating to 1.0](/ERC-7730/sdk/migrating-to-1-0/).

Pass `trust: officialOrLocalPolicy()` to accept an app `extend()` override. Import `attestedPolicy` from `@erc7730/sdk/attest` when the wallet verifies ERC-8176 attestations.

## Context matching

Before a descriptor is applied, `matchContext` must succeed: deployments, EIP-1967 / EIP-1167, factory `deployEvent` logs, EIP-712 domain / `domainSeparator`. A familiar selector on an unbound address is inferred / low — never high under official-only.

## Factory log range

Factory matching calls `Provider.getLogs` only when `fromBlock` is a block number or a tag other than `"earliest"`; otherwise it is skipped with a `FACTORY_RANGE_UNBOUNDED` diagnostic. `toBlock` defaults to `"latest"`. Pass the range via `DecodeOptions` / `MatchContextOptions`.

## ClearSigner

`createClearSigner(options?)` binds `DecodeOptions` for repeated calls. Use its `decodeTransaction`, `decodeTypedData`, `clearSign`, and `extend` methods. The old `decode` alias is removed.
